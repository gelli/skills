# headroom 0.2 plan

Sources: `docs/research/2026-09-27-agentic-trends.md` (web sweep plus Reddit addendum), and a check of the proposed changes against the current Claude Code docs (hooks.md, sub-agents.md, plugins/components.md, agent-teams.md, worktrees.md, tools-reference.md, commands.md, permission-modes.md) on 2026-09-27.

## Outcome

The research supports headroom's core design: one orchestrator that delegates to narrow workers and gets short reports back. The work for 0.2 is fixing enforcement gaps, making the plugin's claims honest, and adding the measurement it currently lacks. Nothing in the evidence justifies a new role or a new cost mode.

## Principles

1. **Measure before tuning.** Every threshold in headroom ("about 3 files", 500 lines, the ~8k-token nudge, "up to five") is a guess. Phase 2 adds the data; thresholds change in Phase 4, not before.
2. **No new settings without data.** This plan adds no user settings.
3. **rules.md budget: at most 430 words** (currently 384). It is injected every session, and ADR 0001 already notes that longer injected text makes delegation less likely. Every addition in Phase 3 names what it replaces.
4. **headroom is not a security boundary.** Say so, and point at `/sandbox` and `permissions.deny`. Don't build guardrails the host already ships.

## What the docs check changed

- **Confirmed:**
  - SubagentStop gets `agent_type`, `agent_id`, `agent_transcript_path`, `last_assistant_message` and `stop_hook_active`, so usage logging per worker can be built.
  - PreToolUse gets `agent_id` only inside subagents.
  - `isolation: "worktree"` works on the Agent call.
  - `worktree.baseRef` accepts `"fresh"` (the default: the repo's default branch) or `"head"`.
  - `SendMessage` resumes a stopped worker, so "the same implementer gets two rounds" is achievable.
  - Plugin agent files support `tools`, `disallowedTools`, `model`, `effort`, `maxTurns`, `isolation`, `background` and `omitClaudeMd`. They ignore `permissionMode`, `hooks` and `mcpServers`.
- **New problem: Explore.** It inherits the main session's model, capped at Opus. `check-agent.sh:100` lets `Explore|Plan` through, and the comment at `check-agent.sh:5` wrongly says they run on their own model. On an Opus orchestrator, every Explore spawn runs on Opus.
- **New problem: agent teammates.** They follow a definition's `tools` list and `model`. `disallowedTools` is not documented as applying to them. Scout and reviewer rely only on `disallowedTools`.
- **New problem: MCP inheritance.** Workers inherit MCP tools unless a `tools` allowlist leaves them out.
- **The research was wrong about:**
  - `/deep-research`: it is a built-in workflow, so rules.md:21 is correct.
  - `persistedOutputPath`: it isn't documented, so the nudge fix that relied on it is dropped.
- **Unverified:** the Opus 5 "don't spawn unless the user requested it" line and auto mode steering towards Bash. Both come from Reddit and GitHub issues, not the docs.
- **Context:** auto mode is the default permission mode since v2.1.283. Pre-authorisation and hard_blocks therefore operate in the normal session, not an edge case.

**Goal:** settle the facts the docs leave open, each of which decides one design choice.

Run every check in a session that actually loads headroom: `claude --plugin-dir ./plugins/headroom`, with model-routing uninstalled or disabled. The two plugins conflict on the Agent hook, and in a model-routing session none of headroom's hooks fire.

### Phase 0 results (2026-09-27, headless `-p` sessions, raw evidence in the session scratchpad)

- **C1, answered.** SubagentStop fired on every worker stop, background and foreground, with `agent_type`, `agent_id`, `agent_transcript_path`, `last_assistant_message` and `stop_hook_active`. `last_assistant_message` was the full report in both modes, including reports delivered as a hand-back. Every assistant entry in the transcript carries `message.model` and `message.usage`. The block works in both modes; the `stop_hook_active` guard resets each time the orchestrator sends the worker a new message. **Decision 4.4: keep the block.** The README claim that background workers bypass it is wrong and gets corrected. The hook's actual limit is 60 lines or 8,000 bytes, a tolerance above the 40-line rule.
- **C2, partial.** A `headroom:reviewer` spawned with `name` still had no Write tool (the `disallowedTools` limit held). Agent teams did not fully engage headless (no team directory, foreground request shape), so a real interactive teammate is untested. 1.3 goes ahead as a cheap guarantee. `check-agent.sh` receives `tool_input.name`.
- **C3, answered, and contradicts the docs check.** For large Bash output, `tool_response` has `stdout` (capped at exactly 30,000 characters), `stderr`, `interrupted`, `isImage`, `noOutputExpected`, and, once the output is persisted, `persistedOutputPath` and `persistedOutputSize`. The model itself sees only a ~2 KB preview plus the path. The nudge therefore fires on every persisted Bash output (tojson ~36.5 KB), but that output never entered the main context: a **false positive**. Read's `tool_response` is `{type, file: {filePath, content, numLines, startLine, totalLines, truncatedByTokenCap}}`, with content capped near 25k tokens. The fix becomes item 1.9.
- **C4, answered.** A worker with the tools allowlist Read, Grep, Glob, Bash, WebFetch, WebSearch saw WebFetch and WebSearch loaded eagerly (not deferred, and no ToolSearch needed), fetched a URL, and handed its report back in both modes. **3.9 is safe as written.**
- **Log location** under `--plugin-dir`: `~/.claude/plugins/data/headroom-inline/headroom.log.jsonl`, shared by every headroom loaded that way.
- **Side finding:** `~/.zshrc:51` aliases `claude` to `claude --allow-dangerously-skip-permissions`. Nested test runs should call `/opt/homebrew/bin/claude` directly.

**Risk:** the debug dumps must not ship. Do them on a throwaway branch.
**Rollback:** delete the branch.

## Remove

- The number "up to five" in rules.md:17. Nothing enforces it and no evidence supports it (3.4).
- "After an inline edit, send a scout to run the tests" (1.6). It spawns a worker for every edit.
- The report block for non-headroom agents (1.1).
- The "delegate this" message on block_patterns matches (1.4).
- The wrong comment at check-agent.sh:5 that Explore and Plan use their own model (1.2).
- Pending C1 and 4.4: possibly the 40-line block itself. Pending 4.5: possibly hard_blocks.

Nothing else. The rest of the design held up against the evidence.

## Rejected, with reasons

- **`thrift` mode that allows lowering a role's model.** It contradicts ADR 0001's core rule and adds a setting before there is any data. Revisit if 2.5 shows raised roles dominate spend.
- **Extending block.sh to `rg`, `grep -r`, `git grep` and `find .`** That grows a text parser with a documented bypass, for a feature that is off by default.
- **A transcript check that fails DONE when no test command ran.** Pattern-matching test commands is brittle, and changes to docs only legitimately run none. 3.8's evidence line does the same job for free.
- **An always-on deny of destructive commands for workers.** headroom isn't a security boundary; `/sandbox` and `permissions.deny` are native.
- ~~**The nudge on `persistedOutputPath`.** The field is not documented.~~ Reversed by C3: the field exists. It is now used the other way round, to *skip* the nudge (1.9).
- **A tools allowlist for scout.** It would cut off MCP docs lookups. The reviewer gets one instead (3.9).
- **Telling users to put an authorisation in their own CLAUDE.md.** It rests on an undocumented claim; 1.8 is the cheap hedge.
- **Announcing every model raise to the user.** Phase 2 logs give the visibility without adding text to the main context.
- **"Split a written plan into one implementer per task."** Sound practice, but it doesn't fit the word budget, and 3.4 plus 3.5 already cover most of it. Revisit if the budget allows.
- **Counting spawns or enforcing a fan-out cap.** That would make check-agent.sh stateful for a limit with no evidence behind it.
- **A spec-writing role or a spec-driven toolchain.** The trend is contested (Thoughtworks has it in "Assess"), and a fourth role lengthens the agent listing.
- **Enforcing "every workflow agent names a model" in check-workflow.sh.** Matching that with a regex over JavaScript is brittle. `CLAUDE_CODE_SUBAGENT_MODEL` applies exactly when no model is set, so the README's fallback recommendation is the right answer.
- **An env-var check for agent teams.** 1.3 (deny `name` on headroom roles) is simpler and works whatever the flag is set to.

## Order of work and release

1. Phase 0 checks, on a throwaway branch, in a headroom session.
2. Phase 1, one commit per item: hooks first, prose second.
3. Phase 2 (needs C1).
4. Phase 3, one implementer per file, in sequence. rules.md word count checked at the end.
5. ADRs 0002 to 0004 and the 0001 update.
6. A fresh opus reviewer does the whole-branch review. Run `sh plugins/headroom/tests/test-hooks.sh` and `claude plugin validate ./plugins/headroom --strict`.
7. Bump to 0.2.0 in `plugin.json`, and in `.claude-plugin/marketplace.json` if it pins versions.
8. Phase 4 stays open until a few weeks of logs exist.

## Status (2026-09-28)

Phases 0 to 3, the ADRs and the 0.2.0 release steps are done on the `headroom` branch. Every group was reviewed. The final opus whole-branch review ran three fix rounds, then a one-word rules.md fix; tests, `plugin validate --strict` and a live nested session all pass.

Additions beyond the table above, all from review:
- log rotation at 10 MB;
- block log lines carry session_id and the command's byte count;
- the transcript readers skip `<synthetic>` entries;
- both transcript readers wait briefly for the final entry, because the Stop and SubagentStop hooks can run before Claude Code writes it (up to a 5 s backstop);
- the test suite's jq/python3 matrices no longer leak `HEADROOM_PARSER` (under macOS `sh`, 9 of 10 "via jq" runs had silently used python3).

Phase 4 stays open. Decided: 4.4, keep the block. The rest wait for their triggers above (4.1 thresholds, 4.2 omitClaudeMd, 4.3 context nudge, 4.5 hard_blocks, 4.6 isolation logging, 4.7 the Explore deny). Run `scripts/usage.sh` after a few weeks of use.

Known minor gaps left by the final review:
- worker usage is grouped by agent type and model, not by session;
- the block log's `bytes` counts the command, not any output;
- a non-object JSON line makes usage.sh fail on the whole log (the hooks never write one);
- CONTEXT.md's "Block" term predates the report-length block on workers;
- the scout and reviewer descriptions still say "changes no project files" without the qualifier.
