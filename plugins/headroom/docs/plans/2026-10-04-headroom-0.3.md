# headroom 0.3 plan

## Goal

Close the two largest remaining leaks of main-context tokens (a whole large file read in place, a model-less Explore or Plan spawn running on the orchestrator's model) and let the session reach for the Workflow tool on its own when a task is big enough.

## Changes

1. **Read guard (new, `hooks/read-guard.sh`, PreToolUse on `Read`).** On by default and not tied to `hard_blocks`; this is a deliberate exception to "blocks are opt-in", because the nudge only fires after the bytes are already in context. In the main session it denies a Read of a file at or over `read_max_bytes` (new setting, default 32768, the nudge threshold; `0` turns it off), unless the Read sets `limit` to 400 or fewer. Never denied: worker Reads (`agent_id` present), images and PDFs, missing files, a session or one-time `/headroom:inline` lift, `HEADROOM_BLOCKS=0`. The reason gives the size in KB and three ways out: `headroom:scout`, a targeted `offset`/`limit` Read, or `/headroom:inline`. Denies are logged like block.sh's.
2. **Explore and Plan need a model (plan item 4.7, done).** `check-agent.sh` denies an Explore or Plan spawn that omits `model`, like general-purpose; the reason says to name a model or prefer `headroom:scout`. Everything else in the check is unchanged.
3. **Workflows (rules.md).** A Workflows section replaces "Workflows run only on the user's request": use the tool without asking for 3+ independent parallel subtasks or a staged pipeline where one stage gates the next, never for single-file changes or one-worker jobs. The pre-authorisation clause now covers running workflows within the session's workflow size guideline and counts as the user's explicit request for multi-agent orchestration. Every `agent()` names a model (never fable, still enforced by `check-workflow.sh`), briefs keep the GOAL / CONTEXT / SCOPE / RETURN shape, and the workflow returns a compact result. `/effort ultracode` stays the user's manual override. rules.md is about 550 words, up from 430.

Principle 2 of the 0.2 plan ("no new settings") held for 0.2; 0.3 adds one, `read_max_bytes`, because the threshold is the one number users will want to move.
